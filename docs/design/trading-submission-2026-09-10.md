# 手动下单边界简化

本批继续 SDK → exchange → Gateway → 个人应用的方向，删除 Trading 中没有实际资金约束能力的独立预留，将手动下单完整用例收进 `manual.Service.Submit`，并修复幂等重放依赖当前账户的问题。

## 删除与保留

| 原设计 | 当前处理 | 原因 |
| --- | --- | --- |
| 独立 reservations 服务、内存/PG 存储、消费 gate | 删除运行时代码、装配、HTTP 路由及前端 wrapper/mock | 原实现只是短暂的账户/品种范围锁，没有冻结余额或保证金；继续维护会让调用者误以为已经预留资金。 |
| 通用 `POST /api/v1/commands` | 删除；命令集合及详情只读 | 当前唯一执行应用是 manual，通用写入口没有独立业务用途，却扩大了绕过应用校验的入口。 |
| HTTP handler 解析账户、选 route、创建预留/命令并派发 | 用例移入 manual 应用服务 | HTTP 只做身份、CSRF、解码、响应与活动发布；应用用例可以直接进行离线测试。 |
| 先查账户/catalog，再判断重放 | 先查原命令，比较用户下单参数 | 账户离线、runtime 变更、写入关闭都不应阻止读取已经受理的订单。 |
| Gateway 客户端用旧修订号合成 `legacy-runtime` | 删除 3 处回退和过期下单字段；响应缺少 runtime ID 明确失败 | 不能把缺失的执行身份补成一个固定字符串。测试夹具同步使用当前契约。 |
| Gateway 生命周期里始终为零的预留阻断计数 | 删除 | 没有数据来源，不应作为可用保护对外描述。订单、未决命令和持仓阻断保留。 |

命令与初始恢复任务仍在同一事务保存。`BeginExecution` 仍通过原子状态转换争取发送权，在请求发往 Gateway 前将命令置为 `uncertain`。Gateway 的账户就绪、runtime 检查、未决订单保护、身份持久化及对账不变。

没有新增通用执行框架、请求账本、事件总线或余额预留系统。以后若出现跨应用资金预算需求，应先定义余额权威、保证金口径和生命周期，再决定是否需要真实资源分配能力。

## 幂等与执行信息

提交身份仍是 `principal + method + path + idempotencyKey`，使用已有唯一约束。

1. 校验请求基本形状，按完整身份查找原命令。
2. 如果存在，比较账户、产品、lineage、命令类型及用户订单字段：instrument、方向、订单类型、数量、限价、timeInForce、reduceOnly、leverage。相同返回原命令，不同返回冲突。订单类型转为小写；数值字符串仍遵循既有的严格比较语义。
3. 如果不存在，检查写入开关、读取账户/catalog、解析 route/runtime、校验品种规则，再保存命令及恢复任务。
4. 两个实例可能同时查不到命令并解析到不同 runtime。存储只允许一个创建成功；输掉创建竞争的一方核对获胜命令中的用户参数，并返回该命令，绝不覆盖它的 route/runtime。
5. 只有新建成功的请求进入执行。任何重放都不会派发，包括 `accepted`。原请求在认领发送前丢失时，既有恢复任务在 30 秒窗口到期后将其标为未发送失败；已经认领但结果不明的命令继续只读对账。

重放不需要新增请求 hash 列：原命令已经保存完整用户参数及所有者。解析出的 route/runtime 是首次受理时的执行信息，仍完整持久化，但不用于判断用户是否改变了意图。不能读取当前 runtime 来重写原命令。

## HTTP 与存储兼容性

- 手动下单/撤单入口仍为 `POST /api/v1/products/manual/commands`，请求字段不变；新操作返回 202，重放返回 200。
- 完整服务及 Auth Edge 对通用命令 POST 返回 405；未注册命令集合的局部测试 mux 返回 404。预留路径不再注册，返回 404。
- 未知字段、第二份 JSON 和非法尾随内容均在进入应用用例前返回 400；header/body 幂等键必须一致。
- 幂等冲突为 409，关闭写入为 403。依赖不可用为 503，不再把未知后端故障伪装成用户参数错误。原始上游错误不写入 HTTP 响应。
- HTTP 契约标识更新为 `boltertrader-product-platform-upgrade/v7`。发布时应配套更新 Trading 和 Auth Edge 的路由定义。
- 本批不新增迁移，Trading schema 保持 **7**。历史 `reservations` 表及 `commands.reservation_id` 保留，供数据库追溯和历史命令读取；旧行状态不再代表当前资源占用。新命令的关联为空，应用不再创建、消费、释放或查询预留资源。既有迁移文件保持不可变。
