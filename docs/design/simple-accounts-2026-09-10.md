# 单人账户接入重设计

用户确认的流程：登录 → 添加交易所凭证 → 查询余额验证 → 交易。
账户只保留添加并验证、查看、删除；换凭证时删除后重新添加。
删除只移除本地凭证与连接，不撤单、不平仓，也不要求交易所先清空持仓。

## 边界

- 平台只判断有没有登录，不提供操作员角色、只读/交易/更新权限、账户 ACL。
  服务间身份验证只是阻止绕过登录的内部机制，不是产品权限模型。
- SDK 实现交易所协议，exchange 规范化调用与错误，Gateway 保存凭证、管理连接、
  读取交易所余额和持仓、提交交易。Trader 不保存另一份凭证或构造交易所客户端。
- 交易所决定 API key 是否有下单、撤单等权限。查询余额成功仅证明这次读取成功，
  不推断交易权限，也不通过试下单检测权限。
- 继续验证订单格式、价格数量精度、产品路由和账户是否存在。SDK 没实现的操作
  仍返回 unsupported；这与交易所的 API 权限是两件事。
- 实盘交易被交易所明确拒绝时保留其错误码和可展示消息；网络超时仍是结果未知，
  不能伪装成拒单，也不能自动重复下单。

## 账户模型

账户是一条已验证的交易所连接配置，不再是一套需要推进的期望状态。

持久化信息仅包括 account_id、venue、display_name、加密后的凭证、created_at、
validated_at。添加请求的幂等键用于生成 account_id，不另建操作日志。凭证与元数据在同一条 INSERT 中原子保存，
不再将一半写进文件、另一半写进数据库，然后依靠凭证操作日志补齐。

连接状态属于内存观察：已连接、连接异常；验证中只是本次请求和表单的临时状态。
新账户不再持久化 creating/candidate_ready/applying/rotating/draining/removed 状态机。
账户 ID 创建后固定，更换 token 或登录密码不改变账户身份；重新添加生成新 ID。

现货、永续、结算币种属于 exchange 的路由知识，由后端按交易所提供，不是用户
勾选的授权范围。表单仅要求交易所真正需要的字段，例如 API key/secret、passphrase、
私钥和必要的子账户参数。

## 添加与删除

添加在一个有超时的请求内完成：校验格式、构造客户端、执行一次合适的余额查询、
保存加密凭证与账户记录、发布可用连接，返回 201。失败直接返回表单，不创建待激活
账户或后台审批任务；零余额同样可以成功。交易所余额接口若为公开地址查询，不将
其成功表述为“已验证签名或下单权限”，私钥格式与地址关联由相应适配器检查。

删除先停止接受该本地连接的新请求，等待已发出的调用结束或达到期限，再关闭连接
并删除本地记录。没有持仓数量、订单数量或产品归属的删除门槛；已经提交到交易所的
订单和仓位保持原样。重新添加后直接读取交易所现状。

## 持仓与订单

交易所余额、持仓、未成交订单是当前账户状态的来源。首次连接获取 REST 快照；
有私有 WS 时用于后续更新，断流后重新获取快照。失败显示不可用或过期，不显示假零。
不根据本地历史成交重建当前持仓，不迁移历史订单归属或做旧 principal 映射。

本地仅保留新交易所需的请求去重、派发结果和结果未知时的查询记录。持仓快照
不能回答某一次下单是否成功，因此这部分记录不能由“直接查持仓”代替。
产品账务若保留，只解释本地记录范围内的费用与盈亏，不能冒充完整交易所历史。

## 删除范围

- 上一批新增的 market_read_token_ref、AccessMarketRead 和固定授权表。
- 账户停用、激活、轮换、更新权限、drain、持仓清空门槛及对应页面操作。
- ProductPolicy 作为账户权限的使用、前端“权限同步”和操作权限矩阵。
- credential operation、desired/active/pending snapshot、promotion/finalization、
  retirement/tombstone 等账户控制面协议与协调器；订单去重和共享行情序号不受此影响。
- token 哈希作为交易订单业务归属的设计。单人实例使用稳定主体，账户以 account_id
  标识；不把凭证当成用户身份，不迁移旧历史订单。
- Trading 为每个 principal 再保存一份交易所持仓的持久投影；保留必要的展示聚合，
  事实与刷新由 Gateway 负责。

## 保留的基础机制

登录会话、HttpOnly Cookie、CSRF、密码哈希；私钥加密落盘、不回传、不记日志；
订单去重、未知结果查询；交易所协议限制与数据新鲜度。它们没有用户授权配置流程。
不为了账户简化把私钥裸存进配置，不把“登录”扩成新的多用户认证系统。

## 验收

1. 未登录不能读账户或发送交易；登录后无需选择角色或额外开通本地交易权限。
2. 正确凭证且余额为零可以添加；错误凭证、超时和限流直接得到可解释错误。
3. 验证不下单、不改单、不撤单；私有流未连上不等于 API key 没有交易权限。
4. 无交易权限的 key 可通过余额验证，下单时返回交易所实际权限错误。
5. 删除有持仓/挂单的账户不触发交易行为；重新添加显示交易所实际状态。
6. 重启恢复已保存账户；私钥不出现在列表、错误、日志或配置打印里。
7. 没有历史订单迁移和隐式重放下单；一条交易请求超时后只能查询确认，不能重发。

## 本次实现与验证

- 新增 `gateway/account/registration.go` 和 `registration_runtime.go`，完成同步验证、
  保存、连接恢复和断开；删除等待本地在途请求，清理失败可以重试。
- 新增 AES-256-GCM 凭证加密，account_id 与 venue 作为认证附加数据。数据库只存密文，
  返回值和格式化日志不包含凭证。前端提交结束后清空输入和 mutation 的 secret 字段。
- 新增迁移 012 与对应数据库契约；旧订单作为证据保留，不迁移归属，不重建持仓。
  旧账户不会自动导入，运行新版本后需要重新添加凭证。尚未在本地执行数据库迁移。
- 对外账户操作与内部 API 均只保留添加、查看、删除；已移除账户 saga、authorityclient、
  候选晋升/轮换的内部协议及页面，取消本地产品权限字段。保留登录、CSRF 和服务间鉴权。
- Trading 每次查询 Gateway 的当前持仓快照，不再启动第二套持仓同步和持久化投影。
  正常空持仓、失败不可用和部分账户失败分别展示；新连接无需本地订单历史。
- 交易所明确的鉴权/权限拒绝被记录为拒单，保留错误码和安全消息；网络不确定性继续查询确认。
  服务 token 更换不改变个人实例的订单主体。
