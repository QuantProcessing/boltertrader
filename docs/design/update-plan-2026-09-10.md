# 个人交易平台更新计划

本计划以当前工作区为基线，接替原始架构审查中的后续计划。旧实施记录保留当时的
决策与测试结果；当前范围、顺序和完成状态统一在这里更新。

## 目标与已确认取舍

目标是 SDK → exchange → Gateway → 个人应用。直接使用 exchange 的 Go 程序不需要
Gateway；使用 Gateway 的 Trader、监控程序不需要 SDK、浏览器内部类型或重复采集器。

- 账户流程：登录 → 添加凭证 → 查询余额验证 → 使用。只保留添加、查看、删除。
- 凭证权限由交易所裁决；技术支持范围与数据健康不伪装成用户授权配置。
- 删除只移除本地凭证与连接，不撤单、不平仓。当前持仓直接读取交易所。
- 保留订单幂等、派发证据和未知结果查询；恢复不自动重复下单。
- 本地资金费套利已删除，不恢复套利页面、双腿执行器或通用策略引擎。
- 费用、返佣、盈亏先按原币种展示；统一币种估值、旧订单归属迁移不在本计划中。
- 保留凭证加密、登录会话和服务身份验证；不扩展角色、ACL 或凭证轮换系统。
- 先在现有进程、数据库与包结构上收敛，不增加消息集群、插件框架或分布式协调服务。

## 已有基线

订单协议修复、历史接单证据、原子状态转换、成交身份范围、命令恢复、原币种费用、
实际 REST 限流与类型化错误、公共/私有 Go 接口分离、基础公开行情 API、账户简化
已经落地。旧 reservations 和账户状态机已删除。详见各批实施记录。

计划启动时基线：96 个 Go 包短测试通过，六个关键包 race 通过，前端 28 个文件的
188 项测试及构建通过。该结果不代表新账户数据库集成或真实交易所验收已完成。

## U1：账户与交易事实验收

工作：

- 在全新隔离 PostgreSQL 中运行当前迁移、凭证密文往返和账户删除测试。
- 真实 HTTP handler、账户服务、Manager、数据库、交易应用持仓读取串联；只有
  交易所使用无凭证假客户端。覆盖登录/代理边界，不只检查 mock 返回形状。
- 覆盖添加零余额账户、余额验证失败不落库、相同请求重放、错误码传递、重启恢复。
- 覆盖外部持仓变化、读取失败不冒充空仓、账户删除后立即消失、删除不发交易请求。
- 覆盖删除后订单事件与幂等记录保留、旧请求不产生新订单、关闭后旧连接不可用。
  Trading 的原币种成交账务继续由现有回归覆盖，不在账户删除时重建或迁移。
- 把验收加入明确的测试入口；默认短测不读取数据库连接环境或交易所密钥。

完成标准：上述跨层测试在隔离数据库通过，并能通过仓库命令再次运行；临时服务关闭；
发现的问题修复并有对应回归。HTTP 集成、浏览器验收和生产环境验证分别标注，互不替代。

## U2：独立 Gateway 客户端

工作：

- 定义中立的 wire DTO 与错误契约；保持 account、instrument、order 身份和数据新鲜度
  含义一致。DTO 不导入 Trading 或其 HTTP 包。
- 建立 `clients/gateway`：账户摘要、余额/持仓、订单提交/撤销/查询、成交、行情目录、
  快照和订阅。接口按实际消费者需求实现，不复制完整 SDK。
- 输入保持严格校验；响应允许兼容性新增字段，并验证必需身份、金额与结果状态。
- 明确超时、取消、响应大小、分页、订阅关闭、断流重订阅和缺口通知。
- 写请求不自动重试；相同意图使用同一个幂等身份。查询失败不能解释为订单不存在。
- 区分服务内部凭证配置与普通应用能力；应用无需自行拼装浏览器接口或处理旧修订号。
- schema、真实 handler 和客户端共享契约验收。代码生成限于减少真实重复，不为此
  引入庞大的自定义生成系统。

完成标准：独立 Go 示例只依赖客户端即可无交易所凭证读取行情；假 Gateway 下可完成
账户状态、下单/查询/撤销、超时恢复测试；新增响应字段不破坏现有客户端，错账户或
错订单身份仍被拒绝。

## U3：应用接入与兼容路径清理

工作：

- Trading 的 Gateway 适配层使用 U2 客户端，只保留应用模型转换。
- 客户端对 `services/trading/httpapi` 的反向依赖已在 U2 移除；继续删除剩余重复 HTTP
  解码和手写接线。
- 前端通过现有登录代理消费统一契约，删除只有浏览器才能使用的重复行情路径。
- 移除旧账户 `requestedState` 等常量兼容字段及对应判断；连接健康只保留实际意义。
- 账户、行情、当前持仓和本地成交账务各自保持明确来源，列表失败不展示为正常空值。
- 补齐余额端点的完整分页/完整性契约。U2 已对达到 500 行上限的响应明确报不完整，
  避免静默截断；迁移旧余额调用方时一并处理。

完成标准：旧 API 的所有仓库调用方完成迁移后才能删除路由；Trader 添加账户、查看
持仓、手动下单/撤销和重放回归通过；新应用不依赖 Trading。

## U4：独立监控验证平台复用

第一版只监控有限标的的价格变化与数据中断，不先建立通用规则语言或监控页面。

- 新增独立命令，使用 U2 客户端消费 BBO/价格；价格口径明确，不把 mark 等同成交价。
- 配置标的、窗口、阈值、最少样本、最大数据间隔和通知冷却。
- 支持数据不足、正常、触发、断流、恢复状态；乱序、重复、过期数据不能产生假告警。
- 仅保存恢复窗口和触发去重所需的状态，不先引入通用通知队列。明确重启后的数据不足
  和重复输出语义；本地通知携带稳定事件身份，不能承诺外部通知恰好投递一次。
- 先实现结构化本地通知输出；真实外部通知渠道、接收目标由用户确认后配置和启用。
- 用确定性事件序列与故障序列测试急跌、延迟、重连、重启，再进行公开行情运行验收。
- 只为该用例需要的数据补 Gateway 能力；OI、资金费、强平等作为之后有需求再接入的
  可选数据集，不为了覆盖清单批量扩展。

完成标准：程序可脱离 Trader、浏览器和交易所凭证运行；不会自行调用 SDK 或维护第二套
交易所连接；故障与重启行为通过回放测试；阈值与通知选择是显式配置。

## U5：交易所知识归位

- 逐项核对 factory、credential、routeprofile、capability、marketcapability 中重复的
  venue/product/settlement/支持字段，先迁移确定的重复数据。
- SDK 负责原生协议和端点元信息；exchange 负责路由、归一化与可选能力；Gateway
  负责采集预算、缓存、连接共享、持久化和服务运行策略。
- 凭证字段描述继续由 credential 模块负责；运行健康继续动态观察。无需把所有模块
  合并进一个包含状态、密钥和 factory 的超级注册表。
- 静态“实现支持”、测试证据和运行状态分开表达，删除固定成功占位字段。
- 核验九家交易所现有关键 REST/WS 路径的错误、数量/金额和关闭语义；测试限制在明确
  支持的产品范围，不通过接口存在就宣称所有账户模式可用。

完成标准：选一个已有交易所走完接入说明，产品层无交易所分支；重复字段有单一来源；
不支持的能力明确返回，不补假值；新增支持遵循同一套协议回归。

## U6：恢复、交付与验收收尾

- 用真实子进程退出/强杀覆盖命令创建、认领发送、HTTP 响应丢失、持久化前后的窗口。
- 处理持续 unknown 的诊断展示：说明最近证据和待处理原因。人工改变订单事实的操作
  需要明确证据与用户意图，不能提供“一键认为失败然后重发”。
- 覆盖 Gateway 重启、Trading 重启、数据库临时断连、单交易所故障、慢订阅消费者。
- 收敛一套单机启动、迁移、健康诊断、备份与恢复说明；先验证现有 Compose，再按实际
  运维成本决定是否需要组合进程入口，不提前拆更多服务。
- 补齐公开网络与代理诊断：U4 隔离验收确认本机直连超时，需要显式设置 HTTP/HTTPS
  代理；不能把已启动、HTTP 健康或目录可读等同于某条实时行情可用。
- 补齐交易页对交易规则的提交前提示，尤其是 U3 浏览器验收发现的最小名义金额提示缺失；
  交易所仍负责最终权限与执行判断。
- 在没有交易凭证的前提下运行全栈和公开行情持续检查；资源使用、断流、订阅释放与
  恢复结果写入验收记录。性能优化由观测结果驱动。
- 新账户流程涉及生产凭证的只读验证、任何真实交易和对外通知启用，均作为明确的
  使用验收动作；当前代码实施授权不等于执行实际交易。

完成标准：有可重复的离线跨层测试、隔离数据库测试、故障测试、浏览器流程与公开行情
运行记录；给出未验证交易所/产品范围；没有与实现冲突的当前使用说明。

## 验证与进度规则

- 状态只用待开始、进行中、已完成、需要讨论，并注明阻碍或证据。
- 常规 Go 回归使用 `go test -short ./...`；竞态检查只覆盖本批并发相关路径。
- 数据库测试必须使用明确的隔离 DSN，记录实例范围；不迁移用户业务数据库。
- UI 改动运行前端测试与构建，交互改动再做浏览器验证。
- 原审查的 F06 以删除套利关闭；F09 以删除虚假预留关闭。F07 的策略资金费归因和
  统一计价币估值不作为当前发布门槛。新的账户完整收益需求需要单独确定范围。
- 每批完成后在下表记录修改、命令、结果与限制；整体进度依据验收交付估计，不以代码行数统计。
