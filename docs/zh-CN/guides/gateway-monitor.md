# 公开行情监控

> 英文为规范版本。[English](../../guides/gateway-monitor.md)

`cmd/gateway-monitor` 是独立 Go 应用，通过 `clients/gateway` 消费 Gateway 的公开
BBO 流。不依赖 Trader、浏览器、交易所凭证、应用数据库或第二套交易所连接。需要
已运行的 Gateway 和其能力面服务令牌；Gateway 本身仍保留现有存储和启动要求。

## 运行

按照[服务指南](exchange-gateway.md)启动 Gateway，用 `GATEWAY_TOKEN` 提供其服务
令牌，再用 [gateway-market](gateway-client.md) 从公开目录选择准确的
`instrument_id`。在 Linux 或 macOS 上运行：

```sh
mkdir -p ./monitor-state
go run ./cmd/gateway-monitor \
  -gateway http://127.0.0.1:18080 \
  -instrument 'binance:live:spot:BTC-USDT' \
  -state ./monitor-state/btc.json \
  -window 1m -change-percent 5 -min-samples 5 \
  -max-gap 10s -cooldown 5m
```

重复 `-instrument` 可监控多个标的，最多 64 个。同一规则分别维护各标的的窗口和
冷却。`-duration 2m` 限制运行时间，默认持续运行至 Ctrl-C 或 SIGTERM。状态文件的
父目录须已存在。命令不加载 `.env`、不接受交易所密钥、不创建账户或订单，仅向
本地输出 JSON 行，不配置任何外部投递渠道。

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `-window` | `1m` | 最大回看窗口，`2s` 到 `1h` 的整数秒 |
| `-change-percent` | `5` | 涨跌幅绝对值阈值，大于 0 且不超过 100，最多 8 位小数 |
| `-min-samples` | `5` | 有有效报价的不同 UTC 秒数，2 到窗口秒数 + 1 |
| `-max-gap` | `10s` | 最大源报价年龄/间隔，`1s` 到窗口长度 |
| `-cooldown` | `5m` | 同一标的价格告警的最短间隔，`1s` 到 `24h` |
| `-state` | 必填 | 单进程独占的本地状态路径 |
| `-duration` | `0` | 到时退出；`0` 表示持续运行 |

## 价格与数据语义

价格使用 decimal 计算的 `(买一 + 卖一) / 2`，不代表成交价或标记价。变化率是
`100 * (当前价格 / 基准价格 - 1)`，基准为窗口内保留的最早报价，上涨和下跌都可
触发。阈值比较不先舍入；输出变化率保留最多 8 位小数。

每个 UTC 秒仅保留第一条有效报价作为基准样本，但每条有效报价都会参与阈值检查，
包含同一秒内的变化。窗口表示最大年龄，不保证积累了完整时长：达到 `min-samples`
个不同秒即开始判断。事件携带实际基准时间、报价时间、价格和样本数。这是相对
窗口起点的收益率规则，不是从滚动最高点计算回撤，也不回补历史。

Gateway 将 BBO 增量推送限制为每 50 毫秒最多一次。监控检查收到的每条报价，并非
交易所原生的每个 tick。BBO 序号递增但跳号是合法的；显式缺口和 generation 切换
仍需要恢复。

畸形协议数据（含非正价格或负数量）被客户端判为协议错误并终止流。通过协议校验
的报价中，零档位数量、买价高于卖价、未来时间、年龄超过 `max-gap`、时间不晚于
上一条有效报价的数据均忽略，因此主机时钟需要同步。无效数据与 WebSocket pong 不会
刷新有效数据时间。每条消息到来前和最长一秒间隔的定时器均检查新鲜度。价格不变
但时间更新仍是有效数据。

Gateway 序号缺口或断连立即进入中断；即使连接存活，源数据超过 `max-gap` 没有
更新也进入中断。中断清空窗口，第一条更新且新鲜的报价产生恢复事件并重建窗口，
不会拿中断前的价格与恢复后的价格比较。

## 本地事件与重启

| `kind` | 含义 |
| --- | --- |
| `state` | 启动、数据不足或回到正常状态 |
| `price_change` | 样本足够、达到阈值且冷却已结束 |
| `interrupted` | 源超时、重同步或流致命终止 |
| `recovered` | 新鲜数据恢复；价格规则仍需要重建窗口 |

`state` 为 `insufficient_data`、`normal`、`triggered` 或 `interrupted`。恢复作为
过渡事件，其状态是 `insufficient_data`。同一标的的涨跌共用价格告警冷却，重启和
断流后仍保留；冷却结束后的新鲜报价如果仍满足阈值，可以再次告警。冷却不抑制
断流、恢复或正常状态诊断。

状态文件仅保存窗口样本、新鲜度、冷却、实例/事件序号以及有限的待输出事件，不
保存凭证。样本最多间隔一秒保存一次，告警先保存再输出。文件使用 0600 权限、
原子替换与文件系统同步。本地 OS 文件锁禁止两个进程共用同一路径，进程退出后
释放；保留 `.lock` 文件，不要在监控运行时删除它。使用支持文件锁与原子替换、
同步语义的本地文件系统。

短暂重启可保留仍新鲜的窗口；状态过期则产生中断并重建，不会虚构缺失报价。崩溃
可能丢失最多一秒没有产生待输出事件的样本。损坏、未来时间或配置不兼容的状态
会阻止启动。修改 Gateway URL、标的集合或规则时使用新状态路径；更换服务令牌
或修改运行时长不使状态失效。

待输出事件重放时保持相同 `id`。如果进程在 JSON 行写出后、状态确认前崩溃，重启
可能重复输出同一行；写入中被杀也可能留下最后一行的残片。消费者需验证完整 JSON
行并按 ID 去重。stdout 写入成功不代表其他进程已持久接收或外部通知已送达。存储
或输出失败会终止程序，不会静默继续。鉴权和协议错误使程序非零退出；网络断连
使用客户端已有的有界退避重连。

## 验证

```sh
make test-monitor
go test -race -short ./services/monitor ./cmd/gateway-monitor ./clients/gateway
```

回放覆盖急跌/急涨、秒内变化、重复/乱序/过期/未来报价、交叉盘口、静默、冷却、
重启、待输出事件和配置不兼容。本机 WebSocket 测试覆盖断连重连、generation
重置、连接存活但数据静默、鉴权失败、取消与订阅释放。公开行情可用性另做运行验收。
